# Plans.md — План реализации электронной системы управления автопарком

## 1. Цель проекта

Разработать настольное приложение Windows для централизованного управления автопарком организации: учёта транспортных средств и водителей, закреплений, страховых полисов, технического обслуживания и ремонтов, запасных частей, контроля критических сроков, уведомлений и отчётности.

**Исходное состояние:** база данных Microsoft SQL Server уже создана. **Не создавать БД заново, не удалять таблицы, не менять существующую схему без отдельного согласования.**

**Технологический стек:** C#, .NET (совместимая поддерживаемая версия), WPF/XAML, MVVM, SQL Server, Entity Framework Core с провайдером SQL Server. IDE — Visual Studio.

## 2. Правила реализации

1. Перед написанием функционала изучить существующий репозиторий, строку подключения (без раскрытия секретов) и фактическую схему БД: таблицы, поля, типы, ключи, ограничения и связи.
2. Использовать подход **Database First**: сгенерировать `DbContext` и сущности из существующей БД либо сопоставить существующие модели с реальной схемой. Не выполнять автоматические миграции и `EnsureCreated`/`EnsureDeleted`.
3. Не выдумывать столбцы. Если функциональность из ПЗ не поддерживается схемой, зафиксировать расхождение и предложить минимальное изменение для согласования. До согласования реализовать доступный функционал.
4. Разделять представления, ViewModel, сервисы бизнес-логики и доступ к данным. Не помещать SQL-запросы и бизнес-правила в code-behind окон.
5. Использовать асинхронные запросы к БД, валидацию вводимых данных, обработку ошибок и понятные сообщения на русском языке.
6. Соблюдать ролевые ограничения не только в интерфейсе, но и в сервисах выполнения операций.
7. После каждого этапа собирать проект и проверять ключевые сценарии. Не переходить к следующему этапу при критических ошибках.
8. Не хранить пароли в открытом виде и не записывать секреты в Git. Если существующая БД содержит небезопасное хранение паролей, отдельно согласовать безопасную миграцию.
9. Не добавлять сложную инфраструктуру (веб-API, микросервисы, облако) без необходимости: проект рассчитан на курсовую работу.

## 8. Правила работы ИИ-агента с этим планом

1. Начинать с аудита проекта и реальной схемы БД, а не с генерации новой базы.
2. Выполнять задачи последовательно, небольшими проверяемыми изменениями.
3. Перед каждым этапом кратко сообщать, какие файлы и компоненты планируется изменить.
4. После выполнения этапа запускать сборку и доступные тесты, исправлять выявленные ошибки.
5. Отмечать выполненные пункты `[x]` в `Plans.md` только после проверки результата.
