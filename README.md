# Электронная система управления автопарком

Учебное приложение для Windows: C#, WPF, .NET 8, Entity Framework Core 9 и SQL Server.
Финальная ветка: **main**. Она включает все предыдущие обновления:
реестры, историю автомобиля, аудит, сброс паролей, отчёты и уведомления.

## Запуск на Windows

1. Установите Visual Studio 2022 с компонентом «Разработка классических приложений
   .NET», .NET 8 SDK и SQL Server/SQL Server Express. Для управления БД используйте SSMS.
2. Скачайте ветку main и распакуйте её в отдельную папку.
3. Подготовьте базу по инструкции ниже.
4. Создайте файл %LOCALAPPDATA%\FleetManagement\connection.txt со строкой подключения
   в одну строку, например:

   ~~~text
   Server=localhost\SQLEXPRESS;Database=ozvs_kursach;Integrated Security=True;Encrypt=True;TrustServerCertificate=False;Connect Timeout=5;
   ~~~

   Укажите свой сервер. Для локального учебного SQL Server с самоподписанным
   сертификатом можно использовать TrustServerCertificate=True. Для удалённого
   сервера настройте доверенный сертификат. Переменная FLEET_CONNECTION_STRING
   имеет приоритет над файлом; после её изменения перезапустите Visual Studio.
   Строку с реквизитами доступа не добавляйте в Git.
5. Откройте «Курсовой проект.sln», восстановите NuGet-пакеты, пересоберите и запустите.

Из PowerShell в корне проекта:

~~~powershell
dotnet build "Курсовой проект.sln"
dotnet run --project "Курсовой проект/Курсовой проект.csproj"
~~~

## Подготовка SQL Server

### Существующая база

Не запускайте database-schema.sql над существующей базой.
В SSMS выберите ozvs_kursach и последовательно выполните:

1. [audit-log.sql](docs/audit-log.sql) — таблица AuditLog.
2. [notification-reads.sql](docs/notification-reads.sql) — таблица личных отметок NotificationReads.
3. При необходимости [database-demo.sql](docs/database-demo.sql) — учебные роли, пользователи и автомобили.

Первые два скрипта можно повторить: уже существующие таблицы не пересоздаются.
Если они применялись ранее, дополнительных изменений для финальной ветки нет.
Автоматических миграций и создания БД при запуске приложения нет.

### Новая учебная база

Только если базы ozvs_kursach ещё нет, выполните [database-schema.sql](docs/database-schema.sql),
затем оба дополнительных скрипта выше и database-demo.sql.
Скрипт исходной схемы создаёт базу с именем ozvs_kursach.
Для отдельной проверочной копии существующей базы используйте восстановление .bak
под другим именем и отдельную строку подключения.

SQL-подключению нужны SELECT на рабочие таблицы; INSERT/UPDATE/DELETE для изменяемых
реестров; SELECT/UPDATE для Roles; SELECT/INSERT для AuditLog и NotificationReads.
Учётная запись SQL Server и роль пользователя приложения — разные уровни доступа.

## Учебные пользователи

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | fleet_admin | TaxiAdmin!2026 |
| Диспетчер | fleet_dispatcher | TaxiDispatch!2026 |
| Механик | fleet_mechanic | TaxiMechanic!2026 |
| Наблюдатель | fleet_viewer | TaxiViewer!2026 |

Данные добавляются database-demo.sql. Скрипт не сбрасывает пароль уже существующего
логина. Это общедоступные учётные записи только для учебной БД.

Регистрация создаёт наблюдателя. Администратор назначает роль и может выполнить
«Сбросить пароль» в разделе пользователей. Пароли хранятся как PBKDF2-SHA256
с солью, не попадают в журнал. Сброс действует при следующем входе;
уже открытый сеанс не завершается автоматически.

Если нужны старые логины из исходного скрипта с открытыми паролями, после резервного
копирования выполните из корня проекта:

~~~powershell
dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --check
dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --confirm
dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --check
~~~

Утилита использует ту же строку подключения. Она предназначена для исходных
открытых паролей, а не неизвестных сторонних хэшей. Готовые PBKDF2-хэши пропускаются.
Для новых демонстрационных пользователей миграция не требуется.

## Возможности и права

| Роль | Изменение данных | Отчёты | Уведомления |
|---|---|---|---|
| Администратор | Все реестры; у ролей только описание | Все | Все |
| Диспетчер | Транспорт, водители, закрепления, документы | Автопарк, расходы, сроки | Страховки и удостоверения |
| Механик | ТО/ремонты, запчасти, состав работ | Расходы, сроки | ТО |
| Наблюдатель | Просмотр | Сроки через колокольчик | Все |

Пользователи и роли видны администратору. Подключение настраивается через файл
или переменную окружения по инструкции выше; отдельного раздела в приложении нет.
История изменений доступна всем: администратор видит все действия, остальные —
только собственные. Подробности открываются двойным нажатием. В журнале сохраняются
создание, редактирование, удаление и факт сброса пароля.

В разделе «Транспорт» кнопка «История автомобиля» открывает закрепления, документы
и обслуживание выбранной машины. Затраты — сумма стоимости сохранённых работ.
Удалённые записи не восстанавливаются в этой истории: их следы остаются в аудите.
Удаление связанных записей запрещено; системные роли не создаются и не удаляются.
Нельзя удалить собственную учётную запись или понизить собственную роль.

## Отчёты

Кнопка «Отчёты» открывает выбор:
- состояние автопарка: текущие машины, статусы, пробег и действующие закрепления;
- обслуживание и расходы: период включительно, автомобиль или весь автопарк;
- предстоящие и просроченные события: список из окна уведомлений.

Экспорт — CSV UTF-8 с разделителем «;», а не XLSX. Если Excel не разделил колонки,
используйте импорт из текста с этим разделителем. Печать использует системный диалог;
для PDF выберите Microsoft Print to PDF. Экспортируется весь сформированный список.
После изменения параметров снова нажмите «Сформировать».
Исторические значения статуса автомобиля и пробега за прошлую дату не восстанавливаются.

## Уведомления

Колокольчик справа вверху показывает непрочитанные события текущего пользователя.
Ноль скрывает кружок; «!» означает ошибку проверки. Всплывающих сообщений нет.
Проверка выполняется при запуске, открытии окна, после сохранения данных и раз
в пять минут, пока приложение работает.

- ОСАГО/КАСКО: за 30 дней и после окончания. Для машины и вида страхования выбирается
  последний вступивший в силу полис. Дата выдачи считается началом действия.
  Будущий полис не заменяет действующий до своей даты выдачи.
- Удостоверения: срок из Drivers. Дубликат в Documents не создаёт второе событие.
- ТО: план следующего ТО из последней выполненной записи ТО/ремонта автомобиля;
  при одинаковой дате выбирается запись с большим ID. Пороги — 30 дней и 1000 км.
  Дата и пробег дают отдельные события. После очередной работы указывайте новый
  актуальный план; пустые поля означают отсутствие плана. Пробег берётся из машины.

«Прочитано» действует только для текущего пользователя и не устраняет проблему.
Изменение срока или переход в просрочку создают новое непрочитанное событие.
Сегодня и точное достижение пробега — наступивший срок; просрочка начинается после.
Исходная Notifications сохранена, но её демонстрационные строки не используются:
предупреждения вычисляются из текущих реестров, отметки хранятся в NotificationReads.

## Ограничения учёта

- Остаток запчастей автоматически не списывается; стоимость ТО вводится отдельно.
  Текущая цена запчастей повторно к расходам не прибавляется.
- Удостоверение в Drivers и документ в Documents автоматически не синхронизируются.
- VIN необязателен, но исходный UNIQUE SQL Server допускает только одну запись с NULL.
- Границы закрепления включены; пересечения по водителю или автомобилю запрещены.
- Журнал показывает последние 1000 доступных событий; поиск работает по загруженным.
- Доступ в приложении не заменяет ограничение прямого доступа к SQL Server.
