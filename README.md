# Электронная система управления автопарком

Курсовой проект: C#, WPF, .NET 8, Entity Framework Core и SQL Server.
Порядок работы — в [Plans.md](Plans.md), результаты аудита — в
[docs/database-audit.md](docs/database-audit.md).

Первый этап проверен пользователем. На втором добавлены вход по логину и паролю,
сессия, выход и права ролей. В главном окне транспорт отображается карточками ListView.
Добавлена самостоятельная регистрация новых пользователей с ролью «Наблюдатель».
Редактирование транспорта запланировано на третий этап.

## Запуск на Windows

1. Установите Visual Studio 2022 с компонентом «Разработка классических приложений
   .NET» и .NET 8 SDK.
2. Используйте существующую базу ozvs_kursach. Файл docs/database-schema.sql —
   справочная копия DDL без тестовых паролей, его не нужно выполнять над готовой БД.
3. Создайте папку %LOCALAPPDATA%\FleetManagement и файл connection.txt.
   Впишите строку подключения одной строкой, например для Windows-аутентификации:

   ```text
   Server=localhost\SQLEXPRESS;Database=ozvs_kursach;Integrated Security=True;Encrypt=True;TrustServerCertificate=False;Connect Timeout=5;
   ```

   Замените сервер на свой. Для учебного локального SQL Server с самоподписанным
   сертификатом допустимо явно поставить TrustServerCertificate=True;
   для удалённого сервера настройте доверенный сертификат.
   Не добавляйте этот файл или пароль в репозиторий.
   Альтернатива — переменная FLEET_CONNECTION_STRING: она имеет приоритет над файлом.
   После изменения переменной перезапустите Visual Studio/приложение.
4. Для исходной БД с открытыми паролями выполните подготовку ниже.
5. Откройте «Курсовой проект.sln», восстановите NuGet-пакеты и запустите проект.

Из PowerShell в папке репозитория:

```powershell
dotnet build "Курсовой проект.sln"
dotnet run --project "Курсовой проект/Курсовой проект.csproj"
```

## Подготовка существующих паролей — один раз

Новая версия принимает только хеши PBKDF2-SHA256 (600 000 итераций, случайная соль).
Логины и пароли для пользователей остаются прежними; меняется только содержимое
Users.Password. Новая БД и новые столбцы не создаются. Открытые пароли не принимаются
даже при правильном вводе, пока подготовка не выполнена.

Утилита предназначена для предоставленного учебного скрипта, где пароли — обычный
текст. Если в вашей БД уже используется иной алгоритм хеширования, не запускайте
преобразование: сначала нужно определить этот формат.

1. Закройте приложение и сделайте резервную копию БД в SQL Server Management Studio:
   база → Задачи → Создать резервную копию → тип «Полная». Сохраните копию вне Git.
2. Используйте ту же настройку подключения, что и для приложения. Для преобразования
   SQL-пользователю нужны права SELECT и UPDATE таблицы Users.
3. В PowerShell из корня репозитория проверьте состояние:

   ```powershell
   dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --check
   ```

   Код завершения 1 означает, что есть неподготовленные записи либо ошибка проверки;
   смотрите сообщение. Код 0 — все записи имеют поддерживаемый формат.
4. Для явного применения после резервного копирования:

   ```powershell
   dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --confirm
   dotnet run --project tools/PasswordMigration/PasswordMigration.csproj -- --check
   ```

   Преобразование выполняется в транзакции. Уже подготовленные записи пропускаются,
   поэтому повторный запуск не изменяет их. Пароли и хеши в консоль не выводятся.
5. Запустите приложение и войдите с прежними логином и паролем.

Старые версии приложения, сравнивающие открытые пароли, после преобразования
несовместимы с новой БД. Не запускайте повторно исходные INSERT пользователей.

## Регистрация

На экране входа нажмите «Создать учётную запись». Заполните фамилию, имя,
необязательное отчество, логин, пароль и подтверждение пароля.

- Логин: 3–100 символов, буквы, цифры, точка, дефис или подчёркивание.
- Пароль: 8–128 символов; подтверждение должно совпадать, включая пробелы и регистр.
- Новая учётная запись всегда получает роль «Наблюдатель». Выбор привилегированной
  роли при самостоятельной регистрации недоступен. Администрирование ролей —
  отдельный будущий этап.
- После регистрации форма закрывается, а логин подставляется на экране входа.
  Введите выбранный пароль для входа.
- Новые пароли сразу сохраняются как PBKDF2-хеши. Утилита преобразования нужна
  только для старых пользователей с открытыми паролями.

В таблице Roles должна быть ровно одна роль с именем «Наблюдатель» — она уже есть
в исходном SQL-скрипте. Регистрация не создаёт роли автоматически и не меняет схему.
Для подключения приложения нужны SELECT на Users/Roles и INSERT на Users.
Уникальность логина при сохранении обеспечивает существующее ограничение UNIQUE
таблицы Users; правила регистра символов определяются collation SQL Server.

Проверка на Windows с вашей БД:

1. Создайте пользователя с новым логином и войдите. Убедитесь, что отображается
   роль «Наблюдатель», вкладка подключения скрыта, транспорт доступен для просмотра.
2. Попробуйте зарегистрировать тот же логин повторно: должна появиться ошибка,
   исходная запись должна сохраниться.
3. Проверьте пустые обязательные поля, короткий пароль и несовпадающее подтверждение.
4. Закройте регистрацию кнопкой «Назад ко входу»: вход должен остаться открытым.
5. При недоступном SQL Server должна появиться понятная ошибка без реквизитов
   подключения. Во время отправки повторная отправка и закрытие регистрации блокируются.
6. После успешной регистрации выйдите и войдите повторно, чтобы проверить сохранение
   пользователя в БД.

## Проверка второго этапа

- Войдите по очереди администратором, диспетчером и механиком; проверьте ФИО и роль.
- Роль «Наблюдатель» сохранена и допускает только просмотр.
- Вкладка «Подключение» доступна администратору. Запрос транспорта требует
  действующей сессии и права просмотра в сервисе, независимо от интерфейса.
- Выйдите и войдите другим пользователем: прежняя сессия и введённый пароль
  не должны сохраняться. Закройте окно входа — приложение должно завершиться.
- Проверьте пустые поля, неверный пароль, неизвестный логин и отключённый SQL Server.
  Главное окно не должно открываться; сообщения не должны показывать детали подключения.
- Enter отправляет форму; повторное нажатие во время входа не запускает второй запрос.
- Проверьте карточки ListView, выделение клавиатурой и изменение размеров окна.

Матрица будущих операций находится в AccessService. На текущем этапе прикладная
операция с автопарком — чтение списка. Защита добавления, редактирования и удаления
будет проверяться вместе с соответствующими сервисами следующих этапов.

## Проверка загрузки транспорта после входа

- При корректном подключении список показывает реальные ТС и количество записей.
- При пустой таблице сообщение явно сообщает, что записей нет.
- При отсутствии настройки/недоступной БД окно остаётся открытым и показывает ошибку.
- Исправьте connection.txt и нажмите «Обновить»: данные должны загрузиться без перезапуска.
- Повторное обновление не должно дублировать строки.
- Проверьте изменение размера окна и переключение вкладок.

На Linux WPF не запускается. Доступна перекрёстная сборка:

```sh
dotnet build "Курсовой проект.sln" -p:EnableWindowsTargeting=true
dotnet test tests/FleetManagement.Tests/FleetManagement.Tests.csproj
```

Автотесты проверяют хеширование, вход, сессию, ролевую матрицу, запрет чтения без
сессии, подготовку паролей, регистрацию и ViewModel. Сценарий «регистрация → вход»
проверяется с тестовым хранилищем. Тесты не подтверждают запуск WPF или SQL-транзакцию
на вашей машине; эти проверки выполняются по инструкции выше.
