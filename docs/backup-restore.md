# Резервная копия и восстановление SQL Server

Проводите итоговые проверки на отдельной учебной копии. Приложение резервных копий
не создаёт; сохранение базы выполняет администратор через SQL Server Management Studio.

## Резервная копия

1. Закройте приложение у пользователей на время подготовки согласованной учебной копии.
2. В SSMS подключитесь к нужному серверу, выберите ozvs_kursach.
3. «Задачи → Создать резервную копию», тип «Полная».
4. Укажите новый файл, например fleet_before_final_2026-10-26.bak.
   Это путь на компьютере SQL Server, доступный его службе.
5. Выполните копирование и убедитесь, что SSMS сообщает об успехе.
6. Храните .bak вне Git: он содержит данные и хэши паролей.

## Проверка восстановления

1. В SSMS выберите «Базы данных → Восстановить базу данных → Устройство» и файл .bak.
2. В качестве назначения укажите **другое имя**, например ozvs_kursach_final_check.
3. На вкладке файлов задайте отдельные пути MDF/LDF для новой базы.
   Не используйте перезапись существующей рабочей базы.
4. Выполните восстановление. Проверьте таблицы, число пользователей и автомобилей.
5. Примените audit-log.sql и notification-reads.sql к восстановленной базе,
   если этих таблиц в копии ещё нет.
6. Настройте приложение на новую базу. Переменная FLEET_CONNECTION_STRING приоритетнее
   файла connection.txt. Для проверки в PowerShell можно задать её только для текущего
   процесса и запустить приложение оттуда.
7. Проверьте вход, чтение реестров и одну обратимую запись, затем зафиксируйте результат
   в чек-листе. Переключение к основной базе выполните отдельно после завершения проверки.

database-demo.sql содержит выбор ozvs_kursach: для иной проверочной базы сначала
откройте копию скрипта и измените её USE на нужное имя. Исходный database-schema.sql
не применяется к восстановленной базе.
