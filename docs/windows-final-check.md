# Итоговая проверка на Windows

Это инструкция для ручной проверки, а не подтверждение её прохождения.
Используйте отдельную копию SQL Server БД и тестовые данные.
Все непроверенные пункты остаются пустыми; «не применимо» поясняйте в примечаниях.

## 1. Чистая установка

- [ ] Скачать финальную ветку в новую папку, открыть именно её .sln, пересобрать.
      Ожидание: сборка без ошибок, запускается актуальное окно с колокольчиком.
- [ ] Настроить подключение к проверочной копии. Проверить приоритет переменной над файлом.
- [ ] Для новой базы выполнить целиком database-install.sql; сверить количество записей
      с результатом скрипта. Повторный запуск должен отказать без удаления данных.
- [ ] Для обновления существующей базы выполнить audit-log.sql и notification-reads.sql.
      Повторить их: существующие записи должны сохраниться.
- [ ] Проверить восстановление .bak по backup-restore.md.
- [ ] После закрытия и повторного запуска данные и настройки доступны.

## 2. Вход и администрирование

- [ ] Войти под каждой из четырёх ролей, сверить доступ с таблицей README.
- [ ] Неверный пароль, неизвестный логин, пустые поля: отказ без технических реквизитов.
- [ ] Зарегистрировать пользователя: роль «Наблюдатель», дубликат логина запрещён.
- [ ] Администратор создаёт пользователя, меняет роль; новая роль доступна после входа.
- [ ] Сбросить пароль тестового пользователя. Старый пароль не работает, новый работает.
      Проверить несовпадающее подтверждение и пароль короче 8 символов.
      Уже открытый сеанс после сброса может оставаться активным — это текущая логика.
- [ ] Собственное удаление и понижение собственной роли запрещены.
- [ ] Изменить роль вошедшего тестового пользователя из другого экземпляра:
      операции с повторной проверкой роли отказывают и предлагают войти заново.

## 3. Реестры

- [ ] Под администратором создать, изменить, найти и удалить тестовую запись каждого
      реестра: транспорт, водители, закрепления, документы, ТО, запчасти, состав работ,
      пользователи. У ролей проверить только изменение описания.
- [ ] Связанные записи создавать после родительских; удалять сначала связи.
      Удаление родителя со связями должно блокироваться.
- [ ] Проверить обязательные поля, отрицательные суммы/количества, даты окончания
      раньше начала, повторные логины, госномера, VIN, удостоверения и артикулы.
- [ ] Проверить пересекающиеся закрепления машины и водителя, включая общую границу дат.
- [ ] Отмена формы не изменяет данные. Двойное нажатие «Сохранить» не создаёт дубль.
- [ ] Открыть одну запись в двух экземплярах; после сохранения первого второй
      не должен затереть изменения старой формой.
- [ ] Проверить те же действия под диспетчером/механиком в пределах их прав;
      наблюдатель только читает. Перезапуск подтверждает сохранение данных.

## 4. История и аудит

- [ ] Для автомобиля открыть «История автомобиля»: данные только выбранной машины,
      вкладки закреплений, документов и работ; пустая вкладка имеет счётчик 0.
- [ ] Итог затрат равен сумме стоимости работ; текущая стоимость запчастей повторно
      не прибавляется. Сверить сумму в SSMS с MaintenanceRepairs по VehicleId.
- [ ] Создание, изменение, удаление и сброс пароля появляются в истории изменений.
- [ ] Двойное нажатие открывает автора, время и понятные данные «было/стало»;
      неизменившиеся поля скрыты, кириллица читается нормально.
- [ ] Пароли/хэши отсутствуют в журнале и экспортах.
- [ ] Администратор видит общий журнал, остальные — только собственные события.
      Поиск по журналу ограничен последними 1000 загруженными событиями.

## 5. Отчёты

- [ ] Автопарк: сверить количество машин и группировку по статусам с реестром.
      Проверить машины без водителя и закрепления, начинающиеся/заканчивающиеся сегодня.
- [ ] Расходы: выбрать машину и период; обе граничные даты включены.
      Сверить сумму и число работ с SQL Server; проверить пустой период и неверный диапазон.
- [ ] После смены параметров нажать «Сформировать»; экспорт отражает параметры результата.
- [ ] CSV открывается в Excel/LibreOffice: кириллица, суммы, кавычки, переносы и «;»
      в описании не разрушают столбцы. Это CSV, а не XLSX.
- [ ] Распечатать многострочный/многостраничный отчёт через Microsoft Print to PDF:
      видны все записи и итог, края текста не обрезаны. Проверить отмену диалога.
- [ ] Отчёт по срокам соответствует фильтру списка уведомлений и правам роли.

## 6. Уведомления

Готовьте даты относительно дня проверки. Пробег изменяйте только на тестовой машине.
- [ ] Полис и удостоверение: осталось 31 день — предупреждения нет; 30 дней — есть;
      сегодня — срок наступает; вчера — просрочено.
- [ ] ТО: осталось 1001 км — предупреждения по пробегу нет; 1000 км — есть;
      точное достижение — срок наступил; превышение — просрочено.
- [ ] Продлить полис новым вступившим в силу документом: старое предупреждение исчезает.
      Будущий полис до своей даты выдачи не заменяет действующий.
- [ ] Новая выполненная запись ТО с актуальным следующим планом заменяет старый план.
      При пустом новом плане предупреждения о следующем ТО отсутствуют.
- [ ] Диспетчер видит документы, механик — ТО, администратор и наблюдатель — всё.
- [ ] Прочитать событие: личный счётчик уменьшается, проблема остаётся в общем фильтре.
      У другого пользователя событие остаётся непрочитанным.
- [ ] Повторно обновить и перезапустить: нет дублей, прочитанность сохраняется.
      Переход в просрочку или изменение срока создаёт новое непрочитанное событие.
- [ ] Счётчик обновляется после сохранения данных и при проверке раз в 5 минут.
      При нуле кружок скрыт; всплывающих сообщений нет.
- [ ] Подробности и переход к истории автомобиля работают.

## 7. Ошибки и интерфейс

- [ ] При недоступной проверочной БД отображаются понятные сообщения.
      Колокольчик показывает «!», а не ложный ноль; повторная проверка после
      восстановления подключения работает.
- [ ] При сохранении ошибка не приводит к частичной записи без аудита.
      При неоднозначном сообщении сначала обновить список, не повторять запись вслепую.
- [ ] Проверить окно обычного размера и развёрнутое, масштаб 100% и 150%,
      длинные ФИО/описания, прокрутку и доступность кнопок.
- [ ] Проверить клавиатуру: Tab, Enter, Escape, видимый фокус колокольчика.
- [ ] Закрытие окна, выход и повторный вход не оставляют чужие данные в интерфейсе.
